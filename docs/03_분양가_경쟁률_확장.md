# 분양가·경쟁률 API 확장 (순서 1)

작성일: 2026-09-25
목표(오너 순서 1): 추천 로직의 근거 데이터로 **분양가**와 **청약 경쟁률**을 기존
수집기와 동일한 요청/파싱 규약으로 통합하고, 수도권 공고에 결합한다.

---

## 1. 선정한 API (모두 청약홈 / odcloud, 이용허락 제한 없음)

| 데이터 | 서비스 | 엔드포인트 | 키 |
|---|---|---|---|
| 목록(기존) | ApplyhomeInfoDetailSvc/v1 | `getAPTLttotPblancDetail` | cond[RCRIT_PBLANC_DE::GTE] |
| **분양가** | ApplyhomeInfoDetailSvc/v1 | `getAPTLttotPblancMdl` | cond[HOUSE_MANAGE_NO::EQ], cond[PBLANC_NO::EQ] |
| **경쟁률** | ApplyhomeInfoCmpetRtSvc/v1 | `getAPTLttotPblancCmpet` | cond[HOUSE_MANAGE_NO::EQ], cond[PBLANC_NO::EQ], (opt) cond[RESIDE_SECD::EQ] |

- 요청/응답 규약은 기존 목록과 동일: `page/perPage/returnType=JSON` + 봉투
  `{page,perPage,totalCount,matchCount,data:[…]}`, 페이징은 `data`<perPage에서 종료,
  키는 Encoding/Decoding 자동 처리(%XX 있으면 그대로).
- 목록에는 분양가·경쟁률이 없어, **공고별 2차 호출(HOUSE_MANAGE_NO+PBLANC_NO 키)**로 결합한다.
- OAS: 분양정보 `https://infuser.odcloud.kr/api/stages/37000/api-docs`,
  경쟁률 `https://infuser.odcloud.kr/oas/docs?namespace=ApplyhomeInfoCmpetRtSvc/v1`.

## 2. 분양가 (getAPTLttotPblancMdl) — 통합 완료

주택형별 상세에서 아래 필드를 읽는다(청약홈 OAS + 동작하는 레퍼런스 수집기로 확인):

| 필드 | 의미 |
|---|---|
| `MODEL_NO` | 주택형 일련 |
| `HOUSE_TY` | 주택형(예: 084.9871A) |
| `SUPLY_AR` | 공급면적(㎡) |
| `SUPLY_HSHLDCO` | 해당 주택형 일반공급 세대수 |
| `LTTOT_TOP_AMOUNT` | **분양가(최고가, 만원)** |

- 앱 처리: 한 공고의 모든 주택형 `LTTOT_TOP_AMOUNT`(만원)를 모아 **최소/최대**를 계산해
  `Notice.priceMinManwon/priceMaxManwon`에 저장(0=미확인). UI에 "분양가 N.N억~M.M억" 표시.
- 코드: `api/ApplyHomeClient.kt`의 `fetchPrice()`. 신규 공고에 한해 `CheckWorker`에서 호출·결합.
- '공고문 참조' 등 숫자 없는 값은 건너뜀(레퍼런스에서 확인된 케이스).
- DB: `Notice`에 분양가 컬럼 2개 추가 → Room v2(재수집 가능 데이터라 파괴적 마이그레이션 허용).

## 3. 경쟁률 (getAPTLttotPblancCmpet) — 요청/스캐폴딩 준비, 라이브 필드 확정 대기

- 엔드포인트·파라미터·페이징 규약은 확정(위 표). **접수가 마감된 공고에만** 값이 존재하며,
  접수 전/진행 중 공고는 빈 결과가 정상이다.
- 주의: 경쟁률 응답의 정확한 필드명은 청약홈 OAS가 제네릭 스키마라 문서만으로는 확정 불가.
  실 응답의 필드명(예: 경쟁률 값 컬럼)을 **라이브로 1건 확인 후** 앱 파서에 반영하는 것이
  안전하다(잘못된 필드명으로 커밋 방지). → `tools/verify_collector.py`가 경쟁률을
  **발견 모드**로 실제 필드/샘플을 출력하도록 구현해 두었다.

## 4. 검증

- `tools/verify_collector.py`는 목록→분양가(주택형별)→경쟁률(발견 모드)를 라이브로 확인한다.
  키는 환경변수 `ODCLOUD_SERVICE_KEY`로만 로드(하드코딩·커밋 금지).
- ⚠️ 이번 사이클에는 **유효 서비스키가 작업 환경에 없어**(직전 사이클 키는 그 사이클
  mission.txt에만 있었고 이번 mission.txt에는 없음) 라이브 실행으로 최종 확인하지 못했다.
  앱 빌드(컴파일) 검증은 완료. 키가 환경변수/앱 설정으로 제공되면 위 스크립트로 즉시
  (1) 분양가 결합 라이브 확인, (2) 경쟁률 필드 확정→앱 파서 반영을 마무리한다.
