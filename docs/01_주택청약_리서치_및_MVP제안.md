# 주택청약 추천·알림 서비스 — 도메인 리서치 & 데이터소스 & MVP 제안

작성일: 2026-09-23
문서 버전: v1 (1차 사이클 산출물)
작성: chungyak-advisor 프로젝트 리더

## 0. 이 문서의 목적

오너 요청("관련 자료 찾아보고 어떤 게 필요한지 리스트업")에 따라, 실제 앱을
만들기 전에 필요한 세 가지를 조사·정리한다.

1. **주택청약 도메인 조사** — 청약 종류, 자격·추천에 필요한 입력 항목, 가점제/추첨제 개요
2. **신뢰할 수 있는 데이터 소스** — 소스별 접근 방법(공식 API / 파일 / 스크래핑),
   이용약관·robots·합법성 검토
3. **MVP 제안** — 위를 바탕으로 한 최소기능제품 범위, 데이터 소스, 입력 스펙

> ⚠️ 주의: 청약 제도(가점 계산, 순위 요건, 특별공급 기준 등)는 「주택공급에 관한
> 규칙」 개정으로 자주 바뀐다(예: 2024-03-25 배우자 통장기간 합산 신설). 본 문서의
> 수치·요건은 리서치 시점 기준이며, **실제 판정 로직 구현 시 청약홈 공고문/법령을
> 최종 확인**해야 한다. 우리 서비스는 "참고용 추천·알림"이며 최종 자격 판정 기관이
> 아니라는 점을 UI에 명시해야 한다(면책).

## 1. 주택청약 도메인 조사

### 1.1 청약 종류 (큰 분류)

| 구분 | 국민주택 | 민영주택 |
|---|---|---|
| 공급 주체 | 국가·지자체·LH·지방공사 | 민간 건설사(래미안, 힐스테이트 등) |
| 면적 | 주거전용 85㎡ 이하 (수도권·도시 외 읍·면은 100㎡ 이하) | 제한 없음 |
| 청약통장 | 주택청약종합저축(구 청약저축) | 주택청약종합저축(구 청약예금·부금) |
| 당첨자 선정 | **순차제**(납입 횟수·저축총액 중심) | **가점제 + 추첨제** |
| 대표 소스 | LH청약플러스, SH 등 지방공사 | 청약홈(applyhome) |

이 서비스의 1차 타깃은 **아파트(APT) 청약**(민영 + 공공/국민주택). 오피스텔·
생활숙박시설·무순위(줍줍)·민간임대 등은 데이터에는 잡히므로 추후 확장 가능.
공모주(IPO)는 범위 밖(오너 확정).

### 1.2 공급 유형: 일반공급 vs 특별공급

- **일반공급**: 일반적인 1·2순위 경쟁. 민영 85㎡ 이하는 가점제+추첨제, 초과는 추첨제 비중↑.
- **특별공급(특공)**: 정책 대상자에게 별도 물량. 종류별 자격이 완전히 다르다.
  - 신혼부부, 생애최초, 다자녀가구, 노부모부양, 기관추천, 이전기관 종사자,
    신생아(2024 신설) 등.
  - 특공은 **소득·자산 기준**이 핵심이고 경쟁이 추첨/배점 혼합. 추천 로직에서
    "이 사용자가 넣을 수 있는 특공 트랙"을 찾아주는 게 큰 가치.

### 1.3 순위 요건 (간단 개요)

- **1순위 기본 조건**: 청약통장 가입기간 충족(규제지역 2년, 그 외 지역별 1~24개월)
  + 지역별 예치금(민영) 또는 납입 횟수(국민) 충족 + 무주택 등 세대 요건.
- 규제지역(투기과열지구·조정대상지역) 여부에 따라 요건이 크게 달라짐 →
  **공급 지역의 규제 상태**가 판정에 중요한 변수.

### 1.4 민영주택 가점제 (85㎡ 이하 일반공급) — 84점 만점

| 항목 | 만점 | 산정 방식 |
|---|---|---|
| **무주택기간** | 32점 | 1년 미만 2점 → 1년마다 +2점 → 15년 이상 32점. 기산일: 만 30세 또는 (30세 이전 혼인 시) 혼인신고일. 과거 주택소유 이력이 있으면 최근 무주택자가 된 날부터. |
| **부양가족 수** | 35점 | 본인 제외. 0명 5점 → 1명당 +5점 → 6명 이상 35점. 등본상 배우자·직계존속(3년 이상 계속 부양)·미혼 직계비속(만 30세 이상은 최근 1년 이상 동일 등본). |
| **청약통장 가입기간** | 17점 | 6개월 미만 1점 → 15년 이상 17점. 최초 가입일(순위기산일) 기준. 미성년 가입기간은 최대 2년만 인정. |

- **배우자 통장기간 합산(2024-03-25 시행)**: 배우자 통장 가입기간 점수의 50%를
  본인 점수에 합산, **최대 3점**. 합산 후에도 통장 점수는 17점을 넘지 못함.
- 만점 예시: 무주택 15년(32) + 부양가족 6명(35) + 통장 15년(17) = 84점.

### 1.5 추첨제

- 점수와 무관하게 무작위 추첨. 주로 **전용 85㎡ 초과** 또는 규제 완화 지역에서 비중↑.
- 무주택 실수요자에게 추첨 물량의 일정 비율을 우선 배정하는 규정이 있음(규제지역).
- 가점이 낮은 사용자에게는 "가점제로는 어렵지만 추첨제 물량이 있는 건"을 추천하는 게 유효.

### 1.6 추천·자격 판정에 필요한 입력 항목 (사용자 프로필 스펙 초안)

아래를 서비스의 **사용자 입력 스키마**로 삼는다. (★ = MVP 필수, ○ = 정확도 향상용)

**세대·주택 보유**
- ★ 무주택 여부 / 주택 소유 이력 (본인+세대원)
- ★ 무주택 기간 (또는 생년월일·혼인신고일로 자동 추정)
- ★ 세대주 여부
- ○ 세대 구성원 수 및 관계(부양가족 계산용): 배우자, 직계존속(부양기간), 미혼 직계비속(나이)
- ○ 과거 청약 당첨/재당첨 제한 이력

**청약통장**
- ★ 청약통장 보유 여부 / 종류(주택청약종합저축 등)
- ★ 가입일(→ 가입기간·순위기산일 자동 계산)
- ★ 납입 인정 회차 / 총 납입금액 (국민주택 순차제용)
- ★ 예치금액 (민영주택 지역별 예치금 충족 판단)
- ○ 배우자 통장 가입일(합산 점수용)

**지역·거주**
- ★ 현재 거주 지역(시/도, 시/군/구) 및 거주 기간 → 해당지역·기타지역 우선 판단
- ★ 관심(청약 희망) 지역

**자금**
- ★ 가용 자금(자기자본) / 대출 가능액 → 분양가 대비 감당 가능 여부 필터
- ○ 소득(월/연) 및 자산 → **특별공급 소득·자산 기준** 판정
- ○ 맞벌이 여부(신혼·신생아 특공 소득기준 완화)

**대상자 속성(특공 매칭)**
- ○ 혼인 여부·혼인 기간(신혼부부 특공)
- ○ 자녀 수·자녀 나이(다자녀·신생아 특공)
- ○ 생애최초 주택구입 여부(생애최초 특공)
- ○ 노부모 부양 여부(노부모 특공)

> 위 항목들로 (a) **청약 가점 자동 계산**, (b) **1순위/특공 자격 필터**,
> (c) **자금 대비 감당 가능 매물 필터**가 가능해진다. 이게 추천 엔진의 입력이다.

## 2. 신뢰할 수 있는 데이터 소스 (합법성 포함)

### 결론 먼저
> **1차 데이터 파이프라인은 공공데이터포털(data.go.kr)의 "한국부동산원_청약홈"
> Open API로 구축한다.** 청약홈 웹사이트(applyhome.co.kr) 직접 스크래핑은
> 불필요하고 리스크가 크므로 지양한다. 청약홈이 커버 못 하는 일부 지방공사
> (SH/GH 등)만 보조적으로 공고 게시판 수집을 검토한다.

### 2.1 ★ 한국부동산원 청약홈 Open API (data.go.kr) — 주력 소스

청약홈의 데이터 원본이 그대로 공공데이터포털에 공개돼 있다. **이용허락범위 제한
없음(영리 이용 포함 자유 활용)** 확인됨. 회원가입 → 활용신청 → 인증키(서비스키)
발급으로 사용. REST, JSON+XML 응답.

| API | data.go.kr ID | 내용 | 우리 용도 |
|---|---|---|---|
| **분양정보 조회 서비스** | 15098547 | APT/오피스텔/무순위·잔여세대/민간임대/임의공급 공고·일정 | ★ 신규 공고·청약 일정 수집(핵심) |
| **청약접수 경쟁률·특별공급 신청현황** | 15098905 | 접수 경쟁률, 특공 신청현황 | 추천 근거(경쟁률), 당첨 가능성 참고 |
| **청약 신청·당첨자 정보 조회** | 15110812 | 지역별·연령별 신청·당첨자, 지역 경쟁률 | 통계·인사이트 |
| **청약통장 통계 조회** | 15114369 | 전체/통장별/가입기간별 가입현황 | 통계(부차적) |
| **(파일) APT 분양정보** | 15101046 | 공고번호·주택명·공급지역·위치·모집공고일 | 백필/대조용 파일 데이터(매월 갱신) |
| **(파일) APT 주택형별 분양정보** | 15101047 | 주택형별 상세 | 분양가·면적별 상세 |

**개발 시 알아둘 실무 포인트(오픈소스 사례에서 확인):**
- 분양 개요(`getAPTLttotPblancDetail`)에는 **분양가 필드가 없다**. 주택형별 상세
  (`getAPTLttotPblancMdl`)의 `LTTOT_TOP_AMOUNT`(단위: 만원)에 있음 → 두 엔드포인트를
  조인해야 "얼마짜리"를 안다.
- 응답은 중첩 없는 **평면 구조**.
- 접수일 필드명이 엔드포인트마다 다름: 아파트 분양 `RCEPT_*`, 무순위
  `SUBSCRPT_RCEPT_*`, 드물게 `GNRL_RCEPT_*`만 채워진 건 존재 → 파서에서 다중 키 처리 필요.
- 개발계정 트래픽 한도 40,000/일(운영계정은 활용사례 등록 후 증량 가능).
  주기 수집이라 한도는 넉넉함.
- ⚠️ 엔드포인트 라우팅(예: `apis.data.go.kr/1613000/...` vs `odcloud.kr`)은
  서비스 프로비저닝 방식에 따라 다를 수 있으니 **활용신청 후 발급되는 기술문서/
  Swagger 명세로 실제 base URL·오퍼레이션명을 확정**할 것.

### 2.2 ○ 한국토지주택공사(LH) 데이터 (data.go.kr) — 국민주택·임대 보완

청약홈 API가 커버하는 범위와 일부 겹치지만, LH 자체 공고(분양·임대) 상세는 LH
데이터가 더 정확할 수 있다.

| API/파일 | data.go.kr ID | 내용 |
|---|---|---|
| 분양주택 입주자 모집공고(파일) | 15112255 | LH 분양 공고문 |
| 분양주택가격공고현황(파일) | 15119323 | 공고명·소재지·세대수·분양가격 |
| 청약센터 공지사항 목록 조회(API) | 15058222 | LH 청약센터 공지 유형·제목·부서·등록일 |
| LH 공고 정보 조회 서비스(API) | (별도) | 공지·채용·분양임대주택 공고 |

- 마이홈포털(myhome.go.kr) 공공데이터 개방 안내상 **누구나·영리 목적 포함 자유 활용 보장**.

### 2.3 △ 지방공사(SH/GH 등) — 실시간 Open API 미제공 → 보조 수집 검토

- SH(서울주택도시공사), HUG(주택도시보증공사) 등 일부는 **실시간 공고 Open API가
  없음**. 필요 시 공개 공고 게시판을 수집(scrape)해야 함.
- 이 경우 **각 사이트 robots.txt의 해당 목록 페이지 수집 허용 여부를 반드시 확인**하고,
  요청 간 간격(rate limit)을 두고, 이용약관 위반·저작권·부정경쟁방지법 리스크를
  개별 검토한다. **MVP에서는 제외**, 확장 단계에서 소스별로 판단.

### 2.4 청약홈 웹사이트(applyhome.co.kr) 직접 스크래핑 — 지양(비권장)

- 청약홈은 한국부동산원(공공기관) 운영. **동일 데이터가 공식 Open API로 이미 개방**돼
  있으므로 웹 직접 크롤링은 명분·실익이 없다.
- 이용약관·저작권·부정경쟁방지법 리스크가 API 대비 크고, 로그인/신청 영역은
  법적으로 절대 접근 금지.
- (참고) 리서치 시점에 `www.applyhome.co.kr/robots.txt`는 404(파일 미제공)로 확인됨.
  robots가 없다고 자유 수집이 허용되는 것은 아님 → **원칙적으로 공식 API 사용**.

### 2.5 도메인 지식 참고 소스(수집 대상 아님, 로직 검증용)

- 청약홈 청약가점 계산기 / 안내 페이지, HUG 주택청약도우미(khug.or.kr): 가점·순위
  로직 **구현 검증용 레퍼런스**로만 사용.

### 2.6 소스별 합법성·접근 요약

| 소스 | 접근 방법 | 라이선스/합법성 | MVP 채택 |

## 3. MVP 제안

### 3.1 MVP 한 줄 정의

> "사용자가 자금·세대·통장·지역 상황을 한 번 입력하면, 주기적으로 수집한 청약
> 공고 중 **넣을 만한 건**을 골라 **추천**하고, 접수 일정을 **알림**으로 보내주는 서비스."

### 3.2 MVP 범위 (In / Out)

**In (이번 앱에서 구현)**
- 청약홈 Open API 기반 **APT 공고·일정 주기 수집 파이프라인**(하루 1~수회 폴링).
- **사용자 프로필 입력**(1.6의 ★ 항목) + **청약 가점 자동 계산**.
- **룰 기반 추천/필터**: (a) 1순위·특공 자격 매칭, (b) 관심 지역, (c) 자금 대비
  분양가 감당 가능, (d) 접수일이 미래인 건.
- **일정 알림**: 접수 시작일 D-N 리마인더 + 신규 매칭 공고 알림.
- 공고 상세(주택형·분양가·경쟁률 참고) 보기.

**Out (범위 밖)**
- 실제 청약 신청 대행(오너 확정 제외).
- 공모주(IPO).
- SH/GH 등 API 없는 소스(확장 단계).
- 개인 금융정보(실계좌 통장 잔액) 연동 — 사용자 수기 입력으로 시작.
- 정밀 당첨확률 예측 모델(초기엔 경쟁률·가점 컷 참고 수준).

### 3.3 데이터 소스 (MVP 확정)

- **주력**: 청약홈 분양정보 조회(15098547) + 주택형별 상세(가격) + 경쟁률(15098905).
- **보완**: LH 파일/공고 API(국민주택·임대 정확도).
- 나머지 통계 API는 인사이트용 차후.

### 3.4 아키텍처 스케치

```
[data.go.kr 청약홈 API]
        │  (스케줄러: 주기 폴링)
        ▼
[수집기 Collector] → 정규화/파싱(필드 다중키·가격 조인) → [공고 DB]
        │
        ▼
[매칭 엔진]  ← [사용자 프로필 DB] (가점 계산 + 자격/자금/지역 필터)
        │
        ├─→ [추천 목록 API/화면]
        └─→ [알림 스케줄러] → 이메일/푸시/카카오/텔레그램 등
```

- 초기 알림 채널은 구현 난이도가 낮은 것부터(이메일 또는 텔레그램/웹푸시).
  카카오 알림톡은 사업자·템플릿 심사가 필요하므로 후순위.

### 3.5 사용자 입력 스펙(MVP 최소 폼)

1.6의 ★ 항목을 최소 폼으로: 무주택 여부/기간, 세대주 여부, 부양가족 구성,
통장 가입일·납입회차·예치금·(선택)배우자 통장, 거주지역·관심지역, 가용자금,
(선택)소득·자산·특공 대상 속성. → 이 입력으로 가점 자동 산출 + 자격/자금 필터.

### 3.6 다음 단계(이번 사이클 이후)

1. data.go.kr 청약홈 API **활용신청·인증키 발급**, 실제 응답 스키마 확정(Swagger).
2. 수집기 PoC: 최근 공고 N건 수집 → 필드/가격 조인/일정 파싱 검증.
3. 가점 계산·자격 판정 룰 엔진 구현 + 청약홈 계산기와 대조 검증.
4. 사용자 프로필 + 매칭 + 알림 파이프라인 → MVP 앱.

> 실제 앱 구축은 규모가 크므로, 오너 승인 시 별도 프로젝트/작업 사이클로 분리 진행 권장.

### 3.7 오너 확인이 필요한 열린 질문

- **플랫폼**: 웹 우선 vs 모바일 앱 우선? (MVP는 웹 반응형 권장)
- **알림 채널 우선순위**: 이메일 / 웹푸시 / 텔레그램 / 카카오 알림톡 중?
- **지역 범위**: 전국 vs 수도권 우선?
- **특별공급 매칭 깊이**: MVP에 특공까지 포함할지, 일반공급부터 시작할지.
