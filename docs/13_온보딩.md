# 13. 첫 실행 온보딩 — v0.9.0

처음 켠 사용자에게 '내 조건'을 단계별로 받아 기존 프로필(ProfileStore)에 저장한다.

## 언제 뜨나
- 자동 표시 조건: `Profile.isSet == false`(거주 시·도 미입력) **그리고** 온보딩을 아직 끝내거나 넘기지 않음.
  - 판정: `ui/Onboarding.shouldShow(profile, done)`.
  - 완료 여부 플래그: `ProfileStore.onboardingDone`(prefs `chungyak_profile`, 키 `onboarding_done`).
- 기존 사용자(v0.8.0까지 조건을 저장함): `isSet == true`라서 뜨지 않는다.
- 조건을 넣은 적 없는 기존 사용자: 업데이트 뒤 한 번 뜬다. '나중에 하기'를 누르면 다시 뜨지 않는다.
- '조건 지우기'를 해도 플래그는 남는다(`clear()`는 프로필·알림 범위만 지움). 그래서 온보딩이 다시 뜨지 않는다.
- 플래그는 프로필과 같은 파일에 있다. 그래서 자동 백업·기기 이전·백업 JSON 모두에서 함께 빠진다.
  프로필 없이 새 기기로 옮기면 온보딩이 다시 뜨는데, 이게 맞는 동작이다.
- 다시 하기: 설정 → '내 조건' 카드 → [온보딩 다시 하기]. 지금 저장된 값이 채워진 채로 시작한다.

## 단계 (`Onboarding.steps` = `FormSection.entries`)
| # | 단계 | 받는 값 |
|---|------|---------|
| 0 | 소개 | [시작하기] / [나중에 하기] |
| 1 | 거주 | 시·도(필수), 시·군·구, 연속 거주 기간 |
| 2 | 세대·주택 | 세대주, 보유 주택 수, 과거 소유, 5년 내 당첨, 특공 당첨 |
| 3 | 혼인·자녀·부양 | 혼인·혼인신고 연월, 미성년 자녀, 2세 미만 자녀, 노부모 부양 |
| 4 | 청약통장 | 종류, 가입 일자(또는 기간), 납입 인정 회차, 예치금 |
| 5 | 소득·자산 | 가구원 수, 소득 %, 맞벌이, 부동산 자산, 소득세 5년 |
| 6 | 청약 가점 | 생년월일, 무주택이 된 날(과거 소유 시), 부양가족 수 + 오늘 기준 가점 카드 |
| 7 | 관심 조건 | 관심 시·도, 분양가 상한, 전용면적 범위 |
| 8 | 알림 범위 | 알림 범위 + 청약 일정 알림 켜기/끄기 |
| 완료 | — | 가점 요약, 다음 할 일(서비스키 없으면 설정으로) |

- 위쪽: "내 조건 입력 n/8", 진행 막대, [나중에 하기]. 아래쪽: [이전] / [건너뛰기] / [다음](마지막 단계는 [완료]).
- 단계마다 머리에 짧은 용어 설명(`FormSection.help`)을 둔다.
- 휴대폰 뒤로 가기: 이전 단계로 간다. 소개나 첫 단계에서는 '나중에 하기'와 같다.

## 저장 규칙
- [다음]: 그 단계의 입력 문제(`Onboarding.problems`)가 없을 때만 넘어간다. 넘어가면서 그때까지의 입력을 바로 저장한다(`saveProfile`).
  중간에 앱을 꺼도 거기까지 입력한 값은 남는다.
- [건너뛰기]: 검증 없이 넘어간다. 그 단계에서 고친 값만 단계에 들어올 때 상태로 되돌리고(`Onboarding.skip`), 저장하지 않는다.
- [나중에 하기]: 이미 저장된 것은 그대로 두고 닫는다. 이후 자동으로 다시 뜨지 않는다.
- 거주를 건너뛰면 `isSet == false`로 남는다. 이때 맞춤 판정은 꺼진 채(모든 공고 알림)이고, 완료 화면에서 이 점을 알려 준다.
- 모르는 값은 비워 둔다. -1(미입력) 처리, '확인 필요' 판정, 부양가족 '추정' 표시는 기존과 같다.

## 재사용 (중복 구현 없음)
- `ui/ProfileDraft.kt`: 입력 상태(숫자 칸 문자열 → `build()`), 검증 `problems()`. 문제마다 묶음(`FormSection`) 표시가 붙는다.
- `ui/ProfileFields.kt`: 묶음별 입력칸(날짜 선택기, 칩, 스위치 등). '내 조건' 탭(`ProfileScreen`)과 온보딩이 같은 함수를 부른다.
- '내 조건' 탭은 묶음 순서(알림 범위 → 거주 → … → 관심)와 저장 동작이 v0.8.0과 같다.

## 데이터 보존
- 프로필 저장 형식(`profile_v1` JSON)은 바뀌지 않았다. 새로 생긴 것은 boolean 키 하나(`onboarding_done`)뿐이다.
- 백업 JSON(`data/Backup.kt`)은 바뀌지 않았다. 프로필은 원래부터 백업에서 빠진다.

## 테스트
- `ui/OnboardingTest`: 첫 실행 판정, 단계 순서, 단계별 검증, 건너뛰기 되돌림.
- `ui/ProfileDraftTest`: 프로필 ↔ 입력 상태 왕복, 빈칸 = 미입력, 검증 묶음 표시.
- `ui/OnboardingScreenTest`(Robolectric Compose): 소개 → 나중에 하기, 시·도 필수 → [다음]에서 저장, 전부 건너뛰기 → 완료, 이전 단계 값 유지.
- `match/ProfileStoreTest`: 플래그 저장·복원, `clear()` 후에도 유지, 기존 사용자(플래그 없음) → 온보딩 안 뜸.
