# 08. 상세 화면 위치 지도 (v0.6.0)

오너 요청(2026-10-03): "목록 세부페이지 들어가면 지도로 위치도 볼 수 있게하자".

## 화면
상세 화면 맨 위 공고 정보 아래에 **위치** 카드:
- 공급위치 주소(청약홈 `HSSPLY_ADRES` 원문)
- 지도 미리보기(높이 200dp, OSM 타일, 마커). 스크롤 화면 안이라 끌기·확대는 막고, **누르면 지도 앱**이 열린다.
- 대략 위치면 "대략적 위치('경기도 수원시 권선구 서둔동' 중심) · 정확한 위치는 지도 앱에서 확인" 문구.
- [지도 앱에서 열기] — `geo:0,0?q=<정리한 주소>` 인텐트. 카카오맵·네이버지도·구글지도 등 설치된 앱(여러 개면 선택창).
  지도 앱이 하나도 없으면 웹(카카오맵 검색)으로 연다.
- 좌표를 못 찾으면 지도 없이 주소 + 안내 + 버튼. 오프라인이면 안내 + [다시 시도] + 버튼. 빈 지도·크래시 없음.

## 키 없는 구성 (오너 지시: 개인 키를 APK·공개 저장소에 넣지 않음)
| 역할 | 사용 | 키 |
|---|---|---|
| 지도 | osmdroid 6.1.20 + OpenStreetMap 표준 타일 | 불필요 |
| 지오코딩 1순위 | Android `Geocoder`(기기 내장, 대개 Google) | 불필요 |
| 지오코딩 2순위 | OSM Nominatim | 불필요 |

정책 준수: Nominatim 초당 1건 이하(앱 전체 Mutex + 1.1초 간격), 앱 식별 User-Agent, 결과 캐시(prefs
`geocode_cache`; 찾음은 영구, 못 찾음은 24시간 뒤 재시도, 네트워크 실패는 캐시 안 함), 사용자가 상세를
열 때만 조회(백그라운드 일괄 조회 없음). OSM 타일: User-Agent = 패키지명/버전, 타일 캐시는 앱 캐시 폴더,
지도 아래 "© OpenStreetMap contributors" 표기. 결과 좌표는 대한민국 범위 밖이면 버린다.

## 주소 정리 (`map/AddressQuery`)
청약홈 공급위치는 "…212-1번지 일원", "…일원(평택고덕국제화계획지구 A65BL)", "…소하동 광명 구름산지구 …A6BL",
"귤현동, 동양동, … 일원 … A17블록", 2026 신설 "화성특례시 만세구"처럼 지오코더가 그대로는 못 찾는 형태가 많다.
→ 괄호·"일원"·"외 N필지"·"번지"·사업지구명 제거, 여러 동 나열은 첫 동만, 행정구역+지번만 남긴 뒤
정확한 것부터 넓은 것 순(지번 → 리/동 → 읍·면 → 시·군·구, 시·도 단독은 안 함)으로 시도. 각 단계마다
"○○특례시 ○○구" → "○○시"(옛 이름)도 시도.

## 검증 (2026-10-03, 청약홈 실제 수도권 공고 14건)
- Nominatim은 한국 지번이 거의 없어 대부분 **동·읍·면 중심**(대략 위치)으로 찾는다 — 14건 모두 좌표 획득.
  실폰의 Android Geocoder는 보통 지번 단위로 더 정확하다(이 환경엔 에뮬레이터가 없어 미확인).
- `GeocodeRepositoryTest.live_realAddresses` (LIVE_GEOCODE=1일 때만): 실제 Nominatim으로 앱 코드 경로를 돌려
  6개 주소의 마커가 해당 동 중심 ±0.03°(약 3km) 안인지 확인. 캐시 재사용도 확인.
- 마커 위치 캡처: `docs/img/map_*.png` (같은 OSM 타일·같은 좌표로 그린 미리보기).

## 키가 필요한 공급자 (쓰지 않음 — 결정은 오너)
- 카카오 로컬 API(주소 검색)·카카오맵 SDK: 한국 지번·도로명 주소 정확도 최상, 지도 품질 좋음. 단 앱 키가 APK에
  들어가야 하고(패키지·서명 해시로 제한 가능하지만 공개 저장소·APK에서 추출 가능), 일 쿼터 공유.
- 네이버 지도 SDK·Geocoding(NCP): 정확도 좋음. 클라이언트 ID 필요, 사용량 과금 가능.
- VWorld(국토부)·도로명주소(juso.go.kr) 검색 API: 공공·무료, 지번 정확. 키 필요(사용자 입력 방식이면 사용자 부담 큼).
→ 지금 구성으로 "대략 위치 + 지도 앱 버튼"까지는 키 없이 충분. 지번 단위 정확도가 꼭 필요하면 위 중 하나를 오너가 선택.

## v0.6.1 — 지도 위 글자 가림 수정
- 방식은 그대로: 공고 주소 → 지오코딩 → osmdroid `MapView`(실제 지도 뷰) 위 `Marker`. 정적 이미지가 아니다.
  `docs/img/map_*.png`는 문서용 미리보기 그림일 뿐 앱에 들어가지 않는다.
- 원인 ①: `AndroidView`로 넣은 osmdroid `MapView`는 가장자리 타일을 자기 영역 밖까지 그리는데, Compose는
  `AndroidView`를 자르지 않는다 → 지도 아래 안내 문구와 [지도 앱에서 열기] 버튼 위로 타일이 덮였다.
  → 지도 칸에 `clipToBounds` + 둥근 `clip`.
- 원인 ②: "대략적 위치 … · © OpenStreetMap contributors" 긴 캡션이 지도 바로 밑에 붙어 있었다(작은 화면·큰 글꼴에서
  여러 줄, 지도와 맞닿음). → 설명 문구는 지도 아래 별도 줄로, 지도 위에는 "© OpenStreetMap"만 오른쪽 아래 구석에
  작고 반투명하게(가운데 마커와 안 겹침).
- 버튼은 지도 아래 별도 줄(`FlowRow`라 좁은 화면·큰 글꼴이면 줄바꿈, 겹치지 않음).
- 마커: osmdroid 기본(초록 핀·손 모양) → 브랜드 파랑 핀(`res/drawable/ic_map_pin.xml`). 정보창은 띄우지 않는다(누르면 지도 앱).
- 검증: `LocationCardLayoutTest`(Robolectric에서 실제 Composable): 360dp/411dp × 글꼴 1.0/1.3, 6가지 상태에서
  주소·문구·버튼과 지도 경계 상자 비교차, OSM 표기가 지도 안 구석에 작게, 그리고 영역 밖으로 그리는 가짜 지도로
  픽셀 번짐 없음(자르지 않은 대조군은 번지는 것도 확인). 스크린샷 `docs/img/v061_*.png`.

## v0.6.2 — 오너 실기기 캡처(v0.6.0) 대조
- 오너 캡처 2장(광명 시티프라디움 에듀하임 / 더샵 분당하이스트, 1440x2937)은 v0.6.0 화면. 증상(지도가 '위치' 제목·주소·버튼을
  덮음, 설명·© 문구가 지도 위, 카드마다 지도 폭이 다름, 초록 손가락 핀)은 모두 위 원인 ①②로 설명된다. 스크롤 위치에 따라
  겹치는 정도가 달랐던 것도 "넘친 타일이 잘리지 않음"과 맞다(폭이 달라 보인 것도 좌우로 넘친 타일).
- 추가 검사 `DetailScreenLayoutTest`(작성만 함 — 빌드 미검증, 아직 실행 안 됨): 상세 화면 전체(`NoticeDetailBody`)에 두 공고를 그대로 넣고, 영역 밖 300px까지 칠하는
  가짜 지도로 25개 스크롤 위치 × (360dp·글꼴 1.3 / 411dp·1.0)를 훑으며 지도 칸 밖 픽셀 0개인지 검사. 두 공고의 지도 좌우
  위치가 같은지, 지도 폭 = 카드 안쪽 폭인지도 검사.
- 위치 카드도 리디자인 2단계 스타일(흰 카드, 18dp 여백, 굵은 제목)로 맞췄다. 배치 규칙은 그대로.
