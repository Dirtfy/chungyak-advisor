# 인앱 업데이트 + 고정 서명 (v0.4.0)

작성일: 2026-10-02

## 1. 덮어쓰기 업데이트 실패 원인 (확인됨)
v0.1.0~v0.3.0 APK는 빌드 컨테이너가 매번 새로 만든 `Android Debug` 키로 서명돼 **세 버전 인증서가 모두 달랐다**
(SHA-256 745423bf…, 13ff6610…, 802f3f49…). 안드로이드는 서명이 다른 APK의 덮어쓰기 설치를 거부한다
(geo-reminder와 같은 원인).

## 2. 해결
- 고정 키: `/workspace/chungyak-advisor/signing/chungyak-radar.jks` + `keystore.properties`
  (저장소 **밖**, 권한 600, 커밋 금지). 인증서 SHA-256
  `e169d6eb3d5513bcf02400c0a9e8f270a9e299bfcd9e7f56a96b30136f3c61ed` (CN=Chungyak Radar, O=Dirtfy).
  `app/build.gradle.kts`가 이 파일이 있으면 debug/release 모두 이 키로 서명. 다른 위치면
  `CHUNGYAK_SIGNING_PROPS` 환경변수. **키를 잃으면 이후 업데이트가 다시 덮어쓰기 불가 → 백업 필수.**
- 빌드는 키가 마운트되도록 상위 디렉터리에서:
  `cd /workspace/chungyak-advisor && project_env.sh chungyak-advisor --image ghcr.io/cirruslabs/android-sdk:34 -- …`
- versionCode = major*10000 + minor*100 + patch (`appVersion` 한 곳만 수정) → 0.4.0 = 400, 단조 증가.
- v0.3.0 이하 → v0.4.0은 키가 달라 **1회 삭제 후 재설치** 필요. 이후부터는 덮어쓰기 업데이트 가능.

## 3. 인앱 업데이트 팝업 (`update/`)
- 콜드 스타트마다 1회 `GET api.github.com/repos/<repo>/releases/latest` (비인증). 저장소는
  `Dirtfy/chungyak-advisor` → 실패 시 `Dirtfy/chungyak-advisor-releases` 순으로 시도.
- `tag_name`(v0.4.0)을 설치된 `BuildConfig.VERSION_NAME`과 숫자 비교(`Versions`, 단위테스트), 새 버전이면 팝업:
  버전 + 릴리스 노트 요약, [업데이트]/[나중에].
- [업데이트]: `.apk` 에셋을 `cacheDir/updates`로 받으며 진행률 표시 → FileProvider(`<pkg>.updates`) +
  ACTION_VIEW로 시스템 설치 화면. `canRequestPackageInstalls()`가 false면 '알 수 없는 앱 설치' 설정 화면 안내.
- [나중에]: 같은 버전을 그 프로세스(실행 세션) 동안 다시 묻지 않음. 네트워크 실패·레이트리밋(60회/h)은 조용히 무시.

## 4. ⚠️ 비공개 저장소 제약
`Dirtfy/chungyak-advisor`는 private이라 비인증 API가 404 → 현재는 팝업이 뜨지 않는다(앱은 정상 동작).
APK에 토큰을 넣는 것은 보안상 하지 않는다. 해결: (A) 저장소를 공개로 전환(소스·이력에 키/비밀 없음 확인) 또는
(B) APK만 올리는 공개 저장소 `Dirtfy/chungyak-advisor-releases` 생성 후 릴리스를 거기에도 게시.
앱은 두 경로 모두 이미 지원하므로 어느 쪽이든 재빌드 없이 동작한다.
