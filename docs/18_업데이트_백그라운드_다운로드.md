# 18. 인앱 업데이트 — 앱을 나가도 다운로드 유지 (v0.13.1)

## 증상 (오너 제보, 2026-10-13)
업데이트 APK를 받는 중에 앱을 나가면(홈 버튼·다른 앱) 잠시 뒤 "인터넷 연결 오류" 계열 실패가 뜬다.

## 재현 판단 (코드 분석 — 실기기·에뮬레이터 없음)
재현된다고 판단했다. v0.13.0의 흐름:
- `UpdateViewModel.update()`가 `viewModelScope.launch { withContext(IO) { UpdateClient.download(...) } }`로
  앱 프로세스 안에서 직접 받았다 (v0.13.0 `UpdateViewModel.kt:87-98`).
- `UpdateClient.download()`는 `HttpURLConnection` + `readTimeout = 60_000` 루프다 (v0.13.0 `UpdateClient.kt:216-249`, `:220`).
- 포그라운드 서비스, WakeLock, WorkManager, DownloadManager 어느 것도 쓰지 않는다.

앱이 백그라운드로 가면 이 프로세스는 "cached" 상태가 된다. Android는 이런 프로세스에
- 앱 대기(App Standby)·Doze 네트워크 차단, 절전 모드 백그라운드 네트워크 제한,
- Android 14+ 캐시 프로세스 동결(freezer — 수 초 뒤 CPU 자체를 멈춤),
- 메모리가 부족하면 프로세스 종료
를 건다. 그러면 소켓 읽기가 멈추고 60초 뒤 `SocketTimeoutException`(또는 `UnknownHostException`/연결 재설정)으로
끝나서 `Failed("timeout"...)` 팝업이 된다 — 오너가 본 "인터넷 연결 오류". 프로세스가 종료되면 `.part` 파일과
진행 상태도 같이 사라져 처음부터 다시 받아야 했다.

## 수정 (v0.13.1)
- **시스템 DownloadManager로 다운로드** (`update/UpdateDownloads.kt`). 시스템 프로세스가 받으므로 앱이
  백그라운드이거나 종료돼도 계속되고, 네트워크가 끊기면 기다렸다가 이어 받는다. 진행 중엔 시스템 다운로드 알림이
  뜬다(앱 알림 권한과 무관). 저장 위치는 앱 전용 외부 저장소 `Android/data/com.chungyak.advisor/files/updates/`
  (권한 불필요, 백업 제외).
- **다운로드 id·릴리스 정보를 prefs(`update_download`)에 저장** → 앱으로 돌아오면(프로세스가 새로 떠도)
  진행률을 이어서 보여 준다. 화면에 있는 동안만 0.5초마다 진행률을 읽는다.
- **완료 시**
  - 앱이 화면에 있으면: 바로 시스템 설치 화면을 열고, 팝업에 [설치] 버튼을 남긴다.
  - 앱이 백그라운드/종료면: `UpdateDownloadReceiver`(DOWNLOAD_COMPLETE)가 "업데이트 준비됨 v… — 탭하면 설치합니다"
    알림(채널 "앱 업데이트")을 띄운다. 탭하면 설치 화면(설치 권한이 아직 없으면 앱을 열어 권한 안내).
  - 알림 권한이 없으면 알림은 생략되고, 앱을 열 때 [설치] 팝업이 뜬다.
- **이미 받은 APK가 있으면** 다시 받지 않는다: 새 버전 확인 시 완성된 파일이 있으면 바로 [설치] 팝업.
- 다운로드 중 팝업에 [숨기기]가 생겼다(다운로드는 계속, 끝나면 다시 알림).
- 업데이트가 설치되면 다음 실행 때 받은 APK와 기록을 지운다.
- `UpdateClient.download()`(직접 다운로드)는 삭제. 릴리스 조회(`latest()`)는 그대로.

## 오너 기기 확인 (빌드·실기기 검증은 CI만, 기기 확인은 오너)
v0.13.1의 개선은 v0.13.1 **다음** 업데이트(v0.13.2 이상)를 받을 때부터 보인다. v0.13.0 → v0.13.1 업데이트는
아직 옛 코드로 받으므로 받는 동안 앱을 켜 두어야 한다.
1. v0.13.1 설치 후, 다음 릴리스가 나오면 [업데이트] → 바로 홈으로 나가기 → 알림창에 시스템 다운로드 진행 표시가 보이는지.
2. 몇 분 뒤 "업데이트 준비됨" 알림이 오는지, 탭하면 설치 화면이 뜨는지.
3. 다운로드 중 앱으로 돌아오면 팝업이 진행률을 이어서 보여 주는지.
4. 다 받은 뒤 알림을 무시하고 앱을 열면 [설치] 팝업이 뜨는지(다시 받지 않음).
5. 비행기 모드를 잠깐 켜면 "네트워크 연결을 기다리는 중"으로 바뀌고, 끄면 이어지는지.

## 장단점
- 장점: 앱 상태와 무관하게 유지·재시도, 코드가 단순(서비스·포그라운드 권한·추가 의존성 없음), 진행 알림은 시스템 몫.
- 단점: 일부 제조사 기기에서 "다운로드 관리자" 시스템 앱을 꺼 두면 시작이 안 됨 → [웹에서 받기]로 우회.
  진행 알림 문구·모양은 시스템이 정한다. 완료 알림은 앱 알림 권한이 있어야 뜬다(없으면 앱 안 팝업만).
