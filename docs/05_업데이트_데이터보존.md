# 05. 업데이트 시 데이터 보존 (v0.4.1~)

## 원칙 (모든 향후 버전에 적용)
1. **같은 applicationId** `com.chungyak.advisor` 유지.
2. **같은 서명 키**: `/workspace/chungyak-advisor/signing/chungyak-radar.jks`
   (cert SHA-256 `e169d6eb3d5513bcf02400c0a9e8f270a9e299bfcd9e7f56a96b30136f3c61ed`).
   저장소 밖 보관, 절대 커밋 금지. 이 키를 잃으면 모든 사용자가 재설치해야 하므로 백업 필수.
3. **versionCode 단조 증가**: `major*10000 + minor*100 + patch` (0.4.1 → 401).
4. **파괴적 마이그레이션 금지**: `fallbackToDestructiveMigration*` 사용 금지.
   DB 스키마를 바꾸면 `AppDatabase.version` 을 올리고 `MIGRATION_n_n+1` 을 **추가만** 한다
   (기존 마이그레이션 삭제·수정 금지). `app/schemas/` 의 내보낸 스키마 JSON 도 함께 커밋.
5. **SharedPreferences 스키마**: `Settings.PREFS_VERSION` + `Settings.migrate()` 단계별 이전.
   키 이름 변경 시 값을 옮기는 단계를 추가한다(기존 키를 그냥 버리지 않는다).
6. 인앱 업데이터는 같은 패키지·같은 키 APK 를 시스템 설치기에 넘기므로 항상 "업데이트"로 설치된다.

## 서명 키 이력
| 버전 | 서명 cert SHA-256 | 비고 |
|---|---|---|
| v0.1.0 | 745423bf… | 빌드 컨테이너 임시 debug 키 — 복구 불가 |
| v0.2.0 | 13ff6610… | 〃 |
| v0.3.0 | 802f3f49… | 〃 |
| v0.4.0~ | e169d6eb… | 고정 릴리스 키 (영구) |

v0.3.0 이하 키는 매 빌드 컨테이너에서 새로 생성된 debug.keystore 였고 컨테이너와 함께 사라졌다
(호스트에 남은 유일한 debug.keystore 는 cert 58:AD:28:CF… 로 어느 것과도 불일치).
따라서 v0.3.0 이하 → v0.4.x 는 1회 재설치가 불가피하며, v0.4.0 → 이후 버전은 덮어쓰기 업데이트.

## 백업 / 복원 (v0.4.1~)
설정 화면 "백업 내보내기 / 백업 가져오기". JSON (`format: chungyak-radar-backup`, `formatVersion: 1`):
설정(서비스키·조회기간·지역·정렬) + 공고 + 주택형 + 경쟁률. 가져오기는 upsert(트랜잭션)이며
기존 데이터를 지우지 않는다. 서비스키가 포함되므로 파일 공유 주의.

## 첫 수집 기준선
재설치 직후 첫 수집은 기존 공고를 "이미 알림" 처리하여 알림 폭주를 막는다(`baseline_done`).

## 업그레이드 검증 (`UpgradeDataTest`, Robolectric sdk 34)
- v1 DB(앱 0.1.0) → v4: 공고·알림여부 보존, 신규 컬럼 기본값
- v3 DB(앱 0.2.0) → v4: 분양가 캐시·주택형 보존
- v4 재오픈: 전체 보존
- 백업 내보내기 → 빈 DB 가져오기 왕복: 설정·데이터 일치
- prefs 0→1 마이그레이션: 기존 설정 보존
- 실제 APK: `apksigner` 로 v0.4.0/v0.4.1 동일 cert, `aapt2` 로 versionCode 400→401 확인.
  (빌드 서버에 KVM 이 없어 에뮬레이터 `adb install -r` 실기 테스트는 불가 — 아래 절차로 실기기 확인)

```
adb install chungyak-radar-v0.4.0.apk      # 데이터 생성(키 입력, 지역 선택, 지금 확인)
adb install -r chungyak-radar-v0.4.1.apk   # Success 여야 함 (INSTALL_FAILED_UPDATE_INCOMPATIBLE 이면 키 불일치)
```
