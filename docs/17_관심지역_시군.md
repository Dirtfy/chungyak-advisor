# 17. 관심 지역 시·군·구 단위 선택 (v0.13.0)

오너 요청(2026-10-10): "관심조건에 지역을 더 세분화하자. 경기는 범위가 너무 커 시 단위로 체크하자."

## 1. 무엇이 바뀌었나

| | AS-IS (v0.12.0) | TO-BE (v0.13.0) |
|---|---|---|
| 고르는 단위 | 서울 / 경기 / 인천 (칩 3개) | 시·도마다 **'OO 전체' 체크** + 펼치면 **시·군·구 칩** |
| 경기 | 경기 전체만 | **31개 시·군** 개별(수원시·성남시·화성시·용인시 …) |
| 서울 | 서울 전체만 | 25개 구 개별(선택) |
| 인천 | 인천 전체만 | 11개 구·군 개별(2026-07-01 개편 반영: 제물포·영종·서해·검단구) |
| 공고 판별 | 공급지역(`SUBSCRPT_AREA_CODE_NM`) 글자만 | 공급위치 주소(`HSSPLY_ADRES`)에서 시·군·구를 읽음 |
| 목록·상세 배지 | "경기" | "경기 수원시" |

화면: '내 조건' 탭 → 관심 조건(온보딩 7단계도 같은 입력칸).
- `☑ 경기 전체` 체크박스는 3단계 — 전체(☑) / 일부(▣) / 없음(☐). 누르면 전체 ↔ 해제.
- `시·군 3/31 ▼`를 누르면 칩이 펼쳐진다. 칩을 켜고 끄면 개별 선택. 31개를 다 켜면 자동으로 '경기 전체'가 된다.
- 위에 "지역 — 지금: 서울 전체, 경기 수원시·화성시"처럼 요약이 나온다. 아무것도 안 고르면 '전체'(예전과 같음).

목업: `docs/img/v013_region_picker.png` (실기기 화면이 아니라 PIL로 그린 그림 — 빌드를 서버에서 돌리지 않으므로).

## 2. 범위 결정 — 왜 서울·인천도 넣었고, 다른 도는 없나

- 앱은 처음부터 **수도권(서울·경기·인천) 공고만 수집**한다(설정 '수집 범위'). 수집하지 않는 도(충남·경남 …)는
  필터를 만들어도 걸릴 공고가 없으므로 만들지 않았다. 수도권 밖으로 넓히는 것은 수집 범위 자체를 바꾸는 별도 작업이다.
- 수도권에서 '넓은 도'는 경기 하나다 → 오너 요청대로 시·군 31개.
- 서울 25구·인천 11구군은 같은 주소 판별기로 공짜로 되기 때문에(목록만 추가) 함께 넣었다. 접혀 있어서
  안 쓰면 예전과 똑같이 'OO 전체' 체크 하나로 보인다.
- 경기의 구(수원시 권선구 등)까지는 내리지 않았다. 일반구는 청약 해당지역 단위가 아니고(해당지역 = 시·군), 칩이 너무 많아진다.
- **설정 > 수집 범위의 '지역(수도권)' 3칩은 그대로** 두었다. 그건 API에서 무엇을 받아 둘지(시·도)이고,
  관심 조건은 받아 둔 것 중 무엇을 알리고 추천할지다.

## 3. 주소 → 시·군·구 판별 (`match/Regions.kt`)

1. 시·도: 공급지역 값(서울/경기/인천)을 먼저 보고, 없으면 주소 앞 낱말(서울특별시·경기도·인천광역시 …).
2. 주소에서 괄호 안(사업지구명 "(평택고덕국제화계획지구 A65BL)" 등)을 지우고 공백·쉼표로 자른다.
3. 낱말이 그 시·도의 시·군·구 이름과 **정확히 같을 때만** 인정(부분 일치 안 함 → "광주광역시"가 경기 광주시로 잡히지 않음).
   특례시 표기("화성특례시", "수원특례시")는 "화성시", "수원시"로 본다.
4. 주소가 두 시·도에 걸치면(예: "인천광역시 계양구 … 서울특별시 강서구 …") 공고 시·도 구간만 본다.
5. 인천 옛 이름(2026-07-01 이전 공고): `동구` → 제물포구, `중구` → 영종도 동(운서·운남·운북·중산·을왕·남북·덕교·무의·용유)이면
   영종구, 아니면 제물포구, `서구` → 검단 지역 동(마전·당하·원당·불로·대곡·오류·왕길·금곡·검단)이면 검단구, 아니면 서해구.
   이렇게 판단한 공고는 상세의 판정 메모에 "옛 행정구역 '중구' 주소 → 영종구로 판단"이 붙는다.

## 4. 매칭 규칙 — 못 읽은 공고는 버리지 않는다

| 공고 | 선택 | 결과 |
|---|---|---|
| 경기 수원시 | 경기 전체 | 포함 |
| 경기 수원시 | 경기 수원시 | 포함 |
| 경기 화성시 | 경기 수원시 | 제외("관심 지역(경기 수원시) 아님") |
| 경기, 시·군 못 읽음 | 경기 수원시(경기에서 하나라도 고름) | **포함 + 메모** "경기 시·군 미확인 — … 경기 관심 공고로 포함(주소 확인)" |
| 경기, 시·군 못 읽음 | 서울 강남구만 | 제외 |
| 시·도도 못 읽음 | 아무거나 | 예전 방식(공급지역·주소 글자에 시·도 이름이 있으면 포함) + 메모 |

메모는 공고 상세의 '내 조건 판정' 카드 아래 회색 글씨로 보인다. 알림·추천순·일정 알림은 모두 같은 판정
(`Eligibility.evaluate` → `filteredOut`)을 쓰므로 한 곳만 바뀌었다.

## 5. 저장·마이그레이션(설정과 알림이 하나도 사라지지 않게)

- 저장 위치는 그대로: 프로필 prefs(`chungyak_profile`)의 JSON `profile_v1`. DB(Room) 변경 없음.
- 새 필드 `interestRegions`: `"경기"`(전체) 또는 `"경기 수원시"`(개별)의 집합.
- **옛 값 이전**: `interestRegions`가 없으면 v0.12.0 이하의 `interestSido`(["경기"] 등)를 그대로 읽는다.
  `"경기"`는 '경기 전체'라는 뜻이라 **31개 시·군 + 시·군을 못 읽은 경기 공고 + 앞으로 생길 시·군까지 모두** 받는다.
  즉 경기를 골라 둔 사용자는 업데이트 뒤에도 경기 공고를 하나도 잃지 않는다(`ProfileStoreTest`, `RegionsTest.legacyProvince_matchesEveryCity`).
- 저장할 때 `interestSido`에도 고른 시·도(일부만 골랐어도 그 시·도)를 같이 써 둔다 → 혹시 옛 버전으로 내려 설치해도
  공고가 빠지지 않고 시·도 단위로 넓게 받는다.
- 알림 범위·일정 알림 설정·보낸 알림 기록은 다른 키라 건드리지 않았다.

## 6. 테스트

- `match/RegionsTest.kt`: 시·군 개수(25/31/11), 실제 주소 형식별 판별(번지·읍면·괄호·특례시·시·도 생략·다중 시·도·인천 옛 이름),
  전체/개별 토글과 자동 합치기, 요약 문구, 매칭(미확인 포함+메모), 옛 "경기" → 31개 시·군 전부 포함.
- `match/ProfileStoreTest.kt`: v0.12.0 JSON(`interestSido:["경기","인천"]`) → 전체 선택으로 읽힘 + 재저장 왕복 + 옛 앱용 필드.
- `match/EligibilityTest.kt`: 시·군 관심 지역 필터와 미확인 메모.

빌드·테스트는 서버에서 돌리지 않고 GitHub Actions(CI)에서만 돌린다.

## 7. 한계

- 주소에 시·군 이름이 아예 없는 공고(예: "○○ 공공주택지구 일원")는 시·군 미확인으로 남는다(포함 + 메모).
- 한 공고 주소에 같은 시·도의 시·군이 여러 개 있으면 모두 그 공고의 시·군으로 본다(하나라도 고르면 포함). 배지는 첫 번째만.
- 인천 옛 '서구'의 검단/서해 구분은 동 이름 목록으로 판단한다(경계 동에서 틀릴 수 있어 메모를 남긴다).
- 행정구역이 또 바뀌면 `Regions.SIGUNGU`와 `AREAS_DATE`만 고치면 된다.
